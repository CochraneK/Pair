进度周期与成本预算：从“设计已准备”走到“可投稿”大约需要多少时间和钱？

下面的预算按当前 A+B+C 规模估算：A 960 条回应、B 324 条、C 576 条，共 1,860 条。这里最主要的成本不是模型调用，而是临床专家时间、人工采集、评分、质检和写作。金额是项目规划假设，不代表任何单位的正式劳务标准。

推荐进度：10–12 周完成真实数据到首轮投稿稿

阶段建议时间主要工作关键产出
1. 最终冻结第 1 周冻结 A/B/C 题目、B/C 系统选择规则、采集 SOP、主要统计方案、伦理/预注册材料可正式执行的 protocol + SAP + freeze package
2. 医生审题与评分校准第 2–3 周A 配对有效性；B/C manipulation、[L,U]、target direction、禁忌行为；评分者 calibration临床 ground truth 与修订后题库
3. 技术小样本 + 正式采集第 3–6 周先跑真实 smoke test，再采集 A/B 消费产品与 C 固定 API；记录版本、时间、错误和 fallback1,860 条真实回应及原始记录
4. 双评分与裁决第 4–8 周两名评分者盲于产品身份独立评分；抽查一致性；按预设规则裁决raw ratings + adjudicated dataset
5. 数据锁定与统计第 8–10 周QA、缺失/异常检查、A 主模型、B/C family-aware 分析、全部图表locked dataset + tables + figures
6. 论文与内部审阅第 10–12 周用真实结果替换占位，补结果/讨论/局限，核对 CHART/声明/附件Paper 1 可投稿稿；PAIR-C pilot 稿

最快：6–8 周

前提是题目几乎不再大改、两名医生每周都能稳定投入、消费产品无明显限额/版本中断、采集与评分并行。适合“先把第一篇尽快投出去”。

推荐：10–12 周

给医生修题、评分一致性、产品版本变化和统计复核留出余量。这个周期更适合作为项目计划。

保守：14–18 周

如果医生时间碎片化、产品频繁升级、题库需要二次临床修订，或两篇论文都要求在同一轮完成，按这个区间更稳妥。

如果 C pilot 成功，扩展到正式 PAIR Benchmark v1

当前 C 的 8 families × 4 axes × 2 levels 是 benchmark-development pilot。若 pilot 通过，扩展到约 20 families、更多有序水平、nuisance-invariance 和正式 release 文档，建议再预留 12–24 周。如果继续采用双临床审核和双评分，新增执行预算可再按 约 ¥30,000–80,000 量级准备；具体数字应等 pilot 后根据保留的轴、水平和模型数重新计算，而不是现在一次性锁死。

项目管理建议：先把“第一篇可投稿”设为 10–12 周里程碑；PAIR-C pilot 可以并行，但正式 benchmark v1 不应成为第一篇投稿的前置条件。这样既保留 benchmark 的长期价值，也不会让原项目被无限扩张拖住。
