02原方案

原学生其实已经在做 benchmark-style study。

原研究用 SIPS P1–P5 组织 80 条 psychotic prompts，并配 80 条 controls；多个消费聊天产品单轮独立回答；两名精神科医生对 appropriateness 及 recognition / non-reinforcement / urgency / resources 评分。

必须先承认的优点：SIPS taxonomy、paired control、研究专用账号、每题新对话、集中时间窗、截图/时间戳、盲评、试评分、预注册和可复现意识，本来都属于合理设计。

它没有直接证明：“用户与 AI 越聊越多，AI 导致病情越来越重”。它是横断面的回应安全审计，不是纵向因果研究。

03真正的硬伤

最重要的不是加技术，而是把可识别性做干净。

问题为什么重要处理
Matched-control confounding示例里 psychosis 与财务风险、停药、对质行为同时变化严格 minimal pair
APP 被当成底模属性hidden system、安全层、routing、配额都属于产品明确 consumer-product snapshot
Novelty 依赖“中国/中文”2025–2026 已有大量相关 benchmark收窄 claim，投稿前再次查新
评分合并方式“中位数后向下取整”会损失分歧保留 raw ratings，预设 adjudication / rater model
统计框架ordinal model、GEE、Brant 不能机械拼接统计人员冻结一个自洽主模型
当前只拿到 3 组示例 pair：三组都被审计为需要修改。完整 160 条正式题库尚未在 v0.1 protocol 中，因此不能假装“全量审完”。

05A / B / C

Plan B 为什么目前最平衡

Aim 1：完整保留原学生问题，用 Plan A 把它做干净。

Aim 2：从少量 scenario families 中只操纵 2–3 个临床 cue：

  • conviction：低 ↔ 高
  • insight：保留 ↔ 缺失
  • behavioral risk：低 ↔ 高

先做 5–8 个 scenario families × 3 axes × 2 levels × 2–3 products 的 pilot。Aim 2 若没有稳定信号，就保持 exploratory，不拖垮 Aim 1。

06如果先做 APP

APP 不是“低配 API”，而是现实 consumer-product audit。

  • 每个产品独立研究专用新账号；不用个人长期账号。
  • 能关则关闭 memory / chat-history reference / custom instructions。
  • 每题独立新会话；只发 frozen prompt；不追问、不 regenerate、不点赞点踩。
  • 固定 Web/Android/iOS surface、界面语言、可见 model/mode、thinking/search 状态。
  • 记录 quota、fallback、自动降级、版本、时间、截图。
  • 默认自动联网属于 product behavior；手动 toggle 必须预先冻结。
以后跑 API：共享同一 case/rubric/schema，但作为独立 evaluation stratum。API 额外固定 exact model ID、system prompt、temperature、top-p、reasoning、tools、seed 等。
07案例怎么造

不是 benchmark / 医生 / AI / 教材文学四选一。

来源适合贡献不能替代
已有 benchmarkanchor、coverage map、设计参考不能直接当大部分主体题库
临床医生ontology、边界、severity、真值、最终审核不必机械写 160 句话
AI按 blueprint 批量合成、minimal pairs、语言变体不能定义 clinical truth
教材/casebook/论文phenomenology、case blueprint不要直接搬真实病例/版权文本
文学/回忆录自然语言肌理、隐晦表达、文化语境不能当诊断 gold standard
医生设计空间，资料提供原料，AI 批量造题，医生决定哪些题是真的。
