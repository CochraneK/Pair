PAIR 的主线不是“做三套方案”，而是把一个研究逐步发展成可复用的 benchmark。

更准确地说，PAIR Benchmark 是主项目，A/B/C 是 benchmark 建设过程中不同成熟度的验证阶段。两篇论文是这套 benchmark 在早期阶段的学术产出，而不是 benchmark 存在的理由。

A：现实世界基线
先验证精神病性内容是否在真实消费产品中更容易触发不恰当回应
B：受控测量桥梁
把“病例”变成 scenario family × clinical axis × minimal contrast
C：benchmark development
系统测量模型是否会随临床信息正确、合比例地改变回应策略
一句话：A 告诉我们“问题是否存在”；B 开始把问题变成可控的测量单元；C 则把这种测量方法发展成可长期复用的 PAIR Benchmark。

A：benchmark 的现实世界基线层

A 不设置“轴”。它保留原 protocol 最核心的对照：精神病性相关版本 vs 严格匹配的非精神病性版本。80 对题目按 SIPS P1–P5 五个维度各 16 对保持平衡，总计 160 条提示词。这个数字主要是继承原研究并保持五个临床内容域均衡，不是通过功效分析推导出的唯一最优数字。

约 5 个消费产品的目的也不是构成“所有模型的代表样本”，而是建立一个有一定现实覆盖面的 consumer-product baseline。最终产品列表需要在真实采集前冻结。

A 对 benchmark 的价值：提供生态有效性。它告诉我们，在用户真实接触到的产品层面，这类问题到底是否存在、表现有多大、是否稳定。

B：从“题库”过渡到“测量仪器”

B 是整个项目第一次真正出现 benchmark 的核心结构：

scenario family × clinical axis × minimal contrast

也就是说，不再只是问“这道题答得好不好”，而是主动控制变量，观察模型是否对一个临床上真正重要的信息变化作出相应调整。

第一轮只选 3 个轴，是为了让临床方向足够清楚，同时避免第一篇无限膨胀：

轴为什么进入 B
确信程度从“我也不确定”到“我完全确定”，理论上应增加澄清、不强化和进一步评估的需要。
对替代解释的接受程度（insight）从愿意考虑其他解释到拒绝其他解释，直接影响现实检验与专业评估的必要性。
即时行为风险从没有据此行动到准备立即做高后果行动，最清楚地测试何时应增加风险评估或转介。

为什么是 6 个基础场景？这是 deliberately small exploratory pilot，而不是最终 benchmark。每个场景做 3 轴 × 2 水平，因此 6 × 3 × 2 = 36 条提示。6 不是“最佳统计数字”，而是为了先验证：医生是否能稳定判断这些 minimal contrasts，模型是否真的呈现可解释信号。如果成功，再扩到 15–20 个 scenario families。

为什么只测 3 个产品、每题 3 次？因为 B 的任务不是重新覆盖整个市场，而是测试这个测量框架是否可行。3 个产品是 A 的有界子集；3 次生成用来估计随机性，不能当成 3 个独立临床案例。

B 对 benchmark 的价值：第一次证明“临床轴”是否真的能被稳定操纵、被医生一致理解，并且产生比简单排行榜更有解释力的模型差异。

C：PAIR Benchmark 的核心开发层

C 不再只是第一篇论文的附加 Aim，而是把 B 的方法独立出来，研究“临床回应校准”本身。这里增加第 4 个轴——证据/普通解释的合理性——因为它并不总是意味着单调升级，有时适当回应可能增加、不变或降低。

C 的设计为什么这样定
8 个场景家族让同一轴在多个不同精神病性表型中重复出现，避免所谓“轴效应”其实只是单一 vignette 特例，同时保持医生逐条审核可行。
4 个轴确信、替代解释接受度、行为风险、证据/合理性分别对应“相信多深、能否动摇、会不会行动、外部依据如何”。
每轴 2 个水平当前 pilot 只检验方向敏感性。真正要测 threshold，关键轴以后必须扩到 ≥3 个有序水平。
3 个固定 API 配置benchmark-development 阶段，模型是“测试测量框架的负载”，不是研究终点；优先要求配置可识别、可重复。
每题 3 次估计同一配置的生成随机性；临床复制单位仍然是 scenario family，不是每一次调用。

所以当前 C 是 8 × 4 × 2 = 64 条提示；3 个固定配置 × 3 次，共 576 条回应。它是 v0 pilot，不是最终版本。

从 pilot 到真正 benchmark 的路线

阶段主要目标可能结构
v0 / 当前验证 ontology、轴、ground truth 与指标是否工作8 families × 4 axes × 2 levels；3 configs
v0.5增加跨场景稳定性与真正 threshold 测量约 15–20 families；关键轴 ≥3 levels；独立 nuisance-invariance 模块
v1.0形成可公开复用、可版本化的 psychosis-specific benchmark核心题库 + clinician annotations + runner/config contract + baseline models + challenge sets + version notes
后续版本长期比较新模型、新产品和干预方法文化 challenge、产品快照、版本漂移、系统提示/RAG 干预等独立扩展

最终想得到的不是一个排行榜，而是“模型临床回应表型”

PAIR 最有价值的结果，不应该只剩下“模型 A 92 分、模型 B 87 分”。更希望得到类似这样的结构：

  • 模型 A：总体校准高，但对 insight loss 的方向敏感性低；
  • 模型 B：对 behavioral risk 很敏感，但容易过度升级；
  • 模型 C：静态回应经常落在可接受区间，却对 evidence/plausibility 的变化反应不足。

这意味着 benchmark 输出的是行为表型和 failure signature，而不只是 leaderboard。
