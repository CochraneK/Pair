A：先把原问题做干净——“精神病性内容本身是否增加回应不恰当风险？”

A 不设置“轴”。它的核心变量只有一个：精神病性相关版本 vs 严格匹配的非精神病性版本。80 对题目来自原 protocol 的整体结构，并按 SIPS P1–P5 五个维度各 16 对保持平衡，因此总计 80 对 / 160 条。这个数字主要是继承原研究并保持五个临床内容域均衡，不是我们重新通过功效分析推导出的唯一最优样本量。

为什么用约 5 个消费产品？因为 A 的目的之一是获得一定的现实产品覆盖，而不是只测试一个模型家族。当前默认集合覆盖多个主流中文消费产品，同时仍能把人工采集和医生评分控制在可执行范围内。最终产品列表必须在看到结果前冻结；它不是“所有中文模型”的概率抽样，因此结论也只限定于被测产品。

A 的优先级：题目覆盖和匹配质量 > 无限增加产品数量。多测 10 个产品并不能补救一个混杂严重的 matched pair。

B：在第一篇里加一个小而清楚的“机制桥梁”

B 保留 A 完整不动，只额外问：如果同一精神病性场景中的一个临床关键信息发生变化，产品的回应策略会不会跟着改变？

第一轮只选 3 个轴，是为了让每个轴都有较清楚的临床含义和预期方向，同时避免把第一篇扩成另一个大型 benchmark：

轴为什么进入 B
确信程度从“我也不确定”到“我完全确定”，理论上应增加澄清、不强化和进一步评估的需要。
对替代解释的接受程度（insight）从愿意考虑其他解释到拒绝其他解释，直接影响现实检验与专业评估的必要性。
即时行为风险从没有据此行动到准备立即做高后果行动，最清楚地测试何时应增加风险评估或转介。

为什么是 6 个基础场景？这是一个有意缩小的 exploratory pilot：每个场景都做 3 个轴 × 2 个水平，因此 6 × 3 × 2 = 36 条提示。6 不是“统计学最佳数字”，而是为了让第一篇仍可完成、医生额外审核量有限，并先判断这种最小对照是否真的能产生稳定、可解释的信号。原计划已经明确：如果 pilot 成功，再扩大到 15–20 个场景家族。

为什么只测 3 个产品、每题 3 次？3 个产品是从 A 的更大消费产品集合中抽取的 pilot 子集，目的是把总量控制在 36 × 3 × 3 = 324 条回应。3 次重复主要用来观察生成随机性，不能把它们当成 3 个独立临床案例。三个产品的最终入选标准应在真实结果出现前写清楚，不能根据 A 的成绩事后挑“最有故事”的产品。

C：把 B 的想法独立出来，研究“临床校准”本身

C 不再依附于原学生项目，而是把 B 中的最小临床对照发展成独立方法学研究。它增加第 4 个轴——证据/普通解释的合理性——因为这一维度不只是“风险更高就应该升级”，有时可能要求增加、不变甚至降低回应强度，更适合放在独立 benchmark 中严谨处理。

C 的设计为什么这样定
8 个场景家族让 4 个轴都在多个不同精神病性表型中重复出现，避免某个轴的结果其实只是某一条 vignette 的特例；同时保持 pilot 可由医生逐条审核。
4 个轴确信、替代解释接受度、行为风险、证据/合理性共同覆盖“相信多深、能否动摇、会不会行动、外部证据如何”四类相对正交的临床信息。
每轴 2 个水平当前 pilot 只回答“方向对不对”，不能精确定位阈值。若 pilot 成功，关键轴应扩展到 ≥3 个有序水平后再谈真正的 threshold/boundary。
3 个固定 API 配置C 首先验证“测量框架能否工作”，所以优先保证配置可识别、可复现，而不是追求市场覆盖。增加更多模型不能替代增加更多临床场景家族。
每题 3 次估计同一固定配置的随机生成波动；临床复制单位仍是 scenario family，而不是每一次 API 调用。

因此当前 C pilot 为 8 × 4 × 2 = 64 条提示；3 个固定配置 × 3 次重复，共 576 条模型回应。原始 benchmark 规划已经预留下一阶段：约 20 个场景家族 × 4 轴 × 2 水平 = 160 条核心提示，再加入独立的无关变量不变性模块。

一句话理解递进：A 先证明“问题存在”；B 小规模问“模型是否理解哪些临床信息会改变处理方式”；C 再把这种能力独立成一个可系统测量的研究对象。
